第一部分　訂餐者操作

1.1 第一次使用前的準備（只需做一次）

  1. 加 EMO 點餐 Bot 為 LINE 好友
    • 掃描單位提供的 Bot QR Code，或點開好友邀請連結
    • 加好友後不需傳任何訊息，只是為了讓系統能把訂單通知推給您
    • ⚠️ 若沒加好友，訂單仍會成立，但您收不到 LINE 確認卡片
  2. 第一次進入訂餐頁
    • 用 LINE 掃描現場貼出的「訂餐 QR Code」
    • 第一次會跳「允許 LINE 帳號授權」→ 按 允許
    • 之後再進入就直接顯示訂餐畫面，不會再問
💡 訂餐網址固定為 https://liff.line.me/<訂餐 LIFF ID>。建議用 LINE 內建瀏覽器開啟，外部瀏覽器無法登入。

1.2 送出一筆訂單

進入訂餐頁後，依下列欄位填寫：

欄位必填說明
單位✅您所屬部門 / 分隊（例：第一勤務組）
訂購人✅您的姓名
警用電話✅內線或聯絡電話
訂購日期✅預設今天；可改成隔日或之後日期預訂
早餐選填下拉選單僅顯示該日已上架的早餐
中餐便當選填A / B / C 三選一，每餐每日上限 40 份；剩餘量會顯示在欄位下方
晚餐便當選填同早餐
備註選填特殊需求、過敏、辣度等

按 送出訂單 後：

  1. 畫面出現綠字：「訂單已送出，感謝您！　您的訂單編號：YYYYMMDD-NNN（請於領餐時出示）」
  2. 幾秒內 LINE 會收到「✅ 訂單已收到」綠色卡片，頂端有訂單編號徽章
  3. 表單會自動清空，可立即為下一位同仁再送一筆
⚠️ 每送一筆是一個獨立訂單。若一人要點多餐多日，請逐筆送出。

1.3 訂單編號的用途

格式：YYYYMMDD-NNN（例如 20260519-007）

  • YYYYMMDD = 訂購日期
  • NNN = 該日第幾筆訂單（從 001 起跳）

領餐時請出示此編號（LINE 卡片上即可看到），管理員會憑此編號核對並標記領餐狀態。

QR 條碼（v5.1 新增）

LINE 訂單確認卡片頂端會附上訂單編號 QR Code：

  • 領餐時把手機畫面亮出 → 管理員用 LIFF 內建相機直接掃描即可帶入編號，免唸出長串數字
  • 即使您看不到 QR（網路問題、舊版 LINE），改用編號口頭告知也可
  • QR 內容就是訂單編號文字本身，不含任何隱私資訊
編號永久寫入試算表，事後查帳、對單都靠它。

1.4 中餐 A/B/C 售完怎麼辦

下拉選單會顯示 （剩 N）：

  • 剩餘量 > 0：可正常選
  • 剩餘量 = 0：該選項變灰、無法點選
  • 想吃的便當售完了：請改選其他餐別，或聯絡管理員確認是否能加單

1.5 進單結單時間 ⏰

每日三餐的訂單最晚截止時間：

餐別進單結單時間取餐時段棄單時間（領餐 deadline）
早餐07:0007:00–08:0008:00
午餐（A/B/C）10:3011:30–12:3012:30
晚餐16:0016:50–18:0018:00
  • 訂購日期 = 今天 且 過了該餐結單時間 → 該餐選項變灰、不可選；強制送出會收到「當日進單已結束」訊息
  • 訂購日期 = 未來日期 → 全部時段都可以訂（cutoff 還沒到）
  • 訂購日期 = 過去日期 → 一律拒收（cutoff 早過了）
💡 v7 起：棄單時間 = 取餐時段結束，語意統一為「領餐時段結束仍未領 → 棄單」。早餐結單 07:00 之後即進入取餐時段。

1.6 預訂明天 / 之後幾天的餐

把「訂購日期」改成未來日期 → 下拉選單會自動切換成該日的菜單。

  • 若該日管理員尚未設定 → 系統自動沿用最近一個有設定的日期作為菜單
  • 若某餐別不供應該日 → 該選項不會出現

1.7 訂單送出後想修改 / 取消

訂餐頁不提供自助修改功能。請：

  1. 紀錄您的訂單編號（送出後 LINE 通知卡片底部會再提醒一次）
  2. 直接聯絡管理員 → 由管理員到試算表手動修正或刪除該列
  3. 如已誤訂，建議愈早通知愈好（廚房可能已備餐；逾時未取消會被計為棄單，詳見 1.7）
💡 v5 起，訂購人收到的 LINE 確認卡片底部會固定附上「需修改 / 取消請聯絡管理員」與棄單時間規則，方便您隨時翻看。

1.8 棄單規則與停權規則 ⚠️

為避免空訂無人領餐造成廚餘浪費，系統自動執行下列規則：

棄單判定（系統自動偵測，無需管理員操作）

餐別棄單時間（= 取餐時段結束）
早餐訂購日當日 08:00 過後仍未領、未取消
午餐（A/B/C）訂購日當日 12:30 過後仍未領、未取消
晚餐訂購日當日 18:00 過後仍未領、未取消
  • 一張訂單若同時點了早、中、晚，各餐獨立判定：只有沒去領的那餐被計為棄單
  • 系統每 10 分鐘自動掃描一次，依訂購日期 + 時段時間判斷
  • 已標記領餐後又被取消 → 若已過時段，下次掃描仍會被判為棄單

停權規則

過去 30 天內棄單超過 3 次（即第 4 次棄單發生時）→ 立刻停止線上訂餐 30 天。
  • 解封日 = 「最新一次棄單時間」+ 30 天
  • 期間若您再嘗試下單，畫面會顯示：
    您最近 30 天內已棄單 N 次（規定超過 3 次即停權），線上訂餐已暫停至 YYYY-MM-DD。如有疑問請聯絡管理員。
  • 停權期間請改用現場登記方式，或聯絡管理員代訂

避免棄單的建議

  • 確認當日確實會用餐再下單
  • 改變主意或臨時有事，請在用餐時段前聯絡管理員取消
  • 若已知會晚到，可請管理員預留並先標記領餐

1.9 訂餐者常見問題

Q1：送出後沒收到 LINE 卡片？

  • 您加 Bot 好友了嗎？沒加就收不到推播
  • 試算表的訂單還是會成立（管理員可從 Sheet 確認）
  • 解法：補加 Bot 好友 → 下一筆訂單會正常收到通知

Q2：畫面顯示「載入菜單失敗」？

  • 通常是網路問題或當日菜單尚未設定
  • 重新整理頁面（LIFF 右上 ⋯ → 重新載入）
  • 仍不行請通知管理員

Q3：訂單編號沒出現在畫面上？

  • 多半是看到舊版快取頁面 → LIFF 右上 ⋯ → 重新載入
  • 即使畫面沒顯示，編號已寫入試算表 K 欄，LINE 卡片上也看得到

Q4：填到一半 LINE 跳掉？

  • 重新開啟 LIFF 即可，填寫內容不會自動保留，需重填
  • 建議資料較長時先在備忘錄寫好再貼上

Q5：訂餐頁某餐選項變灰，旁邊寫「（已截止）」？

  • 該餐當日結單時間已過（早 07:00 / 午 10:30 / 晚 16:00）
  • 解法：把「訂購日期」改成明天 → 該選項會恢復可點

Q6：送出時顯示「當日進單已結束」？

  • 同 Q5；中午後試圖訂今天的午餐就會看到
  • 改選明天即可正常下單

Q7：送出訂單時顯示「線上訂餐已暫停至 YYYY-MM-DD」？

  • 您過去 30 天內棄單已超過 3 次，依規定停權 30 天
  • 期間請改用現場登記或聯絡管理員代訂
  • 待解封日（畫面顯示）之後即可正常使用
  • 若認為判定有誤，請聯絡管理員到試算表查 Orders 工作表 R/S/T 三欄（早/中/晚餐棄單）

第二部分　管理者操作

2.1 進入管理頁

  • 網址：https://liff.line.me/<管理 LIFF ID>
  • 建議用 LINE 內建瀏覽器開啟
  • 進入後需通過白名單驗證：您的 LINE userId 須在試算表 Admins 工作表中
  • 顯示「無管理員權限」代表 userId 沒在白名單 → 請主要管理員協助加入

管理頁畫面由上到下分為四區：

  1. 當日訂單統計（含訂單明細與領餐標記）
  2. 領餐快速查詢（憑訂單編號逐筆對單用）
  3. 每日餐點維護
  4. 「回訂餐頁」連結

2.2 每日餐點維護

這是您每天最常做的事。

平日操作流程

  1. 適用日期：預設今天；要設定未來日期就直接改
  2. 點 載入該日菜單
    • 該日已有資料 → 帶入既有菜單供修改
    • 該日尚無資料 → 系統會把最近一個更早日期的菜單帶進來作為基底
  3. 修改五個欄位（早餐 / 中餐 A/B/C / 晚餐）
    • 欄位留空 = 該餐別當日不供應，訂餐頁下拉選單會自動隱藏該項
    • 例：今天沒有 C 餐 → 「中餐 C」欄清空 → 訂餐頁只剩 A、B
  4. 按 儲存當日菜單
    • 出現綠字「已更新 YYYY-MM-DD 的菜單」即成功
  5. 上方小字「當日已訂｜A x／B x／C x（上限 40）」顯示該日中餐已被訂走的份數，可即時掌握剩餘量

從歷史菜單快速選（v9 新增）

每個輸入欄都附歷史菜單下拉，過去用過的所有名稱都會出現在裡面，最近使用的排最前。

  • 點輸入欄 → 跳出該餐別的歷史菜名下拉清單，直接點選即可填入
  • 打字過濾 → 例如打「滷」，下拉會即時縮到只剩含「滷」的選項
  • 想用新菜名 → 直接輸入新名稱，不必選下拉
  • 儲存後 → 新輸入的菜名會立刻加入下拉，下次可直接點選
💡 歷史是依「餐別」分開的：早餐欄只看到歷史早餐、中餐 A 只看到歷史中餐 A，避免混淆。
💡 歷史菜單永久保留在 Menu 工作表，永遠不會自動清理（每天每餐別一列，可到試算表查歷史紀錄）。

預先排好整週菜單

  1. 把日期切到明天 → 載入 → 修改 → 儲存
  2. 重複到週六、週日
  3. 每天獨立保存，歷史不會被覆寫

重要規則

  • 同一日期 + 同一餐別會覆蓋既有資料；不同日期完全獨立
  • 某日未設定的餐別自動沿用最近一個更早日期（fallback 行為）
    • 例：上週五早餐是「飯糰」，本週一早餐未設定 → 訂餐頁本週一早餐顯示「飯糰」
    • 想讓某日「明確不供應某餐」：把該欄清空後儲存（會寫入空字串，不再 fallback）
  • 修改菜單不影響已送出的訂單

2.3 當日訂單統計

查詢

  1. 日期：預設今天
  2. 點 查詢

看 9 格統計卡片

區塊意義
總筆數該日訂單列數（一人多餐算一筆）
早餐 / 中餐 A / 中餐 B / 中餐 C / 晚餐各餐別訂購份數
早餐已領 x/y早餐已領 x 份 / 訂購 y 份
中餐已領 x/y中餐 A+B+C 合計已領 x 份 / 訂購 y 份
晚餐已領 x/y同上
三個「已領」欄位是 v4 起的新設計：早 / 中 / 晚分開計算。常見情境：早餐都領完了、中餐還有兩單沒來拿、晚餐還沒到領餐時間。

看訂單明細

  • 折疊區「訂單明細 (N 筆)」可展開逐筆檢視
  • 每張訂單卡片：
    • 左上角：訂單編號（深藍徽章）
    • 右側：單位 ｜ 訂購人 ｜ 電話
    • 三列餐點（早 / 午 / 晚）：餐名 + 已領狀態徽章 + 標記按鈕
    • 有備註會在下方以淺色塊顯示

只看未領餐

  • 勾選 只看未領餐 → 列表只顯示「任一餐尚未領」的訂單
  • 用途：收餐尾聲時，把這個過濾打開就一眼看到誰還沒來

2.4 領餐標記（v4 重點功能）

每張訂單卡片上每餐都有獨立的「標記已領／取消已領」按鈕：

  • 點 標記已領 → 該餐徽章變綠「已領 ✓」、按鈕變「取消已領」、時間戳記寫入試算表
  • 點 取消已領 → 還原為「未領」狀態，時間戳清空
  • 上方 9 格統計即時更新，不需重新查詢

兩種典型操作模式

模式 A：客人來櫃台領餐 → 用「領餐快速查詢」

  1. 客人出示 LINE 卡片或唸出訂單編號
  2. 在「訂單編號」輸入框輸入（例 20260519-007）→ Enter
  3. 該訂單卡片顯示在下方，含三列餐點
  4. 對應領的餐別點 標記已領
  5. 換下一位客人 → 編號欄位手動清空後輸入新編號（不會自動清，方便核對前一單）

模式 B：批次發餐 → 用訂單明細列表

  1. 在「當日訂單統計」展開明細
  2. 勾「只看未領餐」
  3. 逐筆對人 → 點 標記已領
  4. 全部處理完，未領數字應歸 0

2.5 領餐快速查詢

獨立區塊（在訂單統計與菜單維護中間）：

  • 用途：櫃台領餐時，不必先查詢統計、不必展開明細，直接打編號就帶出該單
  • 輸入框支援 Enter 直接送出
  • 找不到會紅字提示「查無此單」
  • 找到後與明細卡片功能相同：可逐餐標記領餐
💡 訂單卡片最下方會顯示每餐的領餐時間戳，可用來核對是否重複領餐。

📷 掃描 QR 條碼（v5.1 新增）

按下「📷 掃描 QR」按鈕，會跳出 LINE 內建相機掃描器：

  1. 對準訂購人 LINE 卡片頂端的 QR Code
  2. 掃描成功後自動帶入訂單編號並立即查詢
  3. 該單顯示後，點對應餐別的「標記已領」即可
⚠️ 首次使用前：需請當初部署系統的人到 LINE Developers Console 把 管理 LIFF 的「Scan QR」開關打開（一次性設定）。
若按鈕跳「此 LINE 版本不支援 QR 掃描」，請更新 LINE App 至最新版（iOS 10.13+ / Android 10.16+）。

2.6 中餐 A/B/C 每日上限與進單結單時間

  • 中餐每餐預設 40 份 / 天；訂滿後訂餐頁該選項變灰、無法選
    • 想調整：見《安裝手冊》後台屬性 LUNCH_DAILY_LIMIT（如未設則為 40）
    • 想單日加開：目前沒有後台介面，需手動到 GAS 改常數或重新部署
  • 三餐進單結單時間（v5）：早 07:00 / 午 10:30 / 晚 16:00
    • 過此時間後，訂餐頁該餐選項自動變灰
    • 規則寫在 Code.gs 的 ORDER_CUTOFF 常數中；要調整就改該常數並重新部署 GAS

2.9 棄單與停權（v5）

系統會自動執行棄單偵測與訂餐者停權，管理員平日不需手動操作；本節說明判定邏輯與例外處理。

棄單自動判定

  • 每 10 分鐘 trigger 掃描一次
  • 條件：訂單某餐 = 已訂購 + 未領 + 未棄單 + 訂購日期當日已過該餐 cutoff 時間
  • cutoff（v7：對齊取餐時段結束）：早餐 08:00 / 午餐 12:30 / 晚餐 18:00（試算表時區，預設 Asia/Taipei）
  • 偵測完寫入 Orders 工作表的 R / S / T 欄（早/中/晚餐棄單，TRUE / FALSE）
⚠️ 若新部署或剛升級到 v5，請到 Apps Script 編輯器執行一次 setupAbandonmentTrigger 建立 trigger，否則棄單欄不會自動更新。

停權自動判定

  • 在使用者下單當下即時計算
  • 規則：過去 30 天內棄單次數 > 3 → 自動拒收新訂單
  • 解封日 = 最新一次棄單時間 + 30 天
  • 後端回覆訊息會顯示停權原因與解封日，前端訂餐頁直接顯示

管理員例外處理

情境處理方式
訂購人因公事無法領餐，不該記為棄單到 Orders 工作表找到該列，把對應的 R / S / T 欄改回 FALSE
訂購人申訴停權判定有誤同上，把該人累計到 3 次以上的棄單記錄改為 FALSE，下次下單即放行
想提前解封找出該人最近一筆棄單，把對應的 R/S/T 欄改 FALSE（或直接刪除該列）
想查某人棄單紀錄Orders 工作表，J 欄篩該人 userId、R/S/T 欄篩 TRUE
想暫停整個棄單機制Apps Script → trigger 頁面 → 移除 markAbandonedOrders 即可（不影響既有資料）

第三部分　廚房接單人員（v6 群組通知 + v10 結單彙整）

廚房人員不需要進管理頁、也不需要個別加 Bot 為好友。新訂單通知統一發到指定的廚房 LINE 群組。

3.1 第一次使用

  1. 請管理員把您加入廚房 LINE 群組（例：「EMO 廚房接單群」）
  2. 確認群組成員清單裡有 EMO 點餐 Bot（由管理員邀請；若不在請通知管理員處理）
  3. 之後每筆新訂單會自動在群組推播，您只要看群組就好

3.2 接單通知

每當有人成功送出訂單，群組會收到「🍱 新訂單」橘色 Flex 卡片，包含：

  • 訂單編號
  • 訂購日期、單位、訂購人、電話
  • 訂購的早餐 / 中餐 / 晚餐
  • 備註
通知是 LINE 群組 push 推播。若同時多筆訂單可能稍微延遲幾秒，屬正常範圍。

3.3 群組沒收到通知怎麼辦

依序排查：

  • Bot 是否還在群組裡？打開群組成員清單確認
  • 群組通知是否被靜音？檢查群組右上 ⋯ → 通知設定
  • 個人手機 LINE 通知是否被關？檢查手機 LINE App 通知權限
  • 請管理員到 Apps Script「執行記錄」看是否有 New-order group push failed 字樣

3.4 暫停接單通知（休假 / 排假）

  • 個人短期靜音：群組對話右上 ⋯ → 通知 → 關閉。收假時自行打開，不需通知管理員
  • 長期離職：通知管理員把您從群組踢出即可

3.5 每餐結單彙整訊息（v10 新增）

除了「每筆下單」的接單通知，廚房群組另會在每餐結單時段收到一則彙整：

餐別結單時間彙整推送時機
早餐07:0007:00 後 5 分鐘內
中餐10:3010:30 後 5 分鐘內
晚餐16:0016:00 後 5 分鐘內

彙整訊息為純文字 1 則，內容含：

  • 各餐製作量統計（中餐分 A / B / C）
  • 訂購人名單（單位、姓名、品項、備註）
  • 已取消訂單獨立列出（標明「不需準備」）
收到彙整訊息後再開工，可避免遺漏臨時加單；個別 push 與彙整 push 兩者並行。

第四部分　管理 LINE 群組收件人（v11 新增）

此章節給「只負責看每日日報 / 月報」的主管或單位代表參考。 若您同時是管理員，可直接看第二部分 §2.11。

4.1 您會收到什麼

每日 18:00 後 5 分鐘內：📊 EMO 日報

純文字訊息，內容包含：

  • 訂單總計、有效 / 已取消
  • 三餐 訂 / 領 / 棄統計
  • 中餐 A / B / C 分項
  • 領餐率 ／ 棄單率
  • 訂購單位 TOP 5（哪個單位訂得多）

每月 1 日 09:00 後 5 分鐘內：📊 EMO 月報

純文字訊息，內容包含：

  • 涵蓋工作日數
  • 累計訂單總數
  • 三餐累計、中餐 A / B / C
  • 領餐率、棄單率
  • 訂購單位 TOP 10
  • 棄單紀錄 TOP 5（哪些人棄單最多）

4.2 收到後可以做什麼

  • 複製到文書工具或 Excel 做進一步分析（純文字格式，方便貼上）
  • 在 LINE 群組就地討論（@相關人員）
  • 單位督導：若某單位棄單率異常，可即時提醒
  • 採購規劃：依當月 A/B/C 比例調整未來菜單配比

4.3 沒收到訊息怎麼辦

  • 群組通知是否被靜音？（群組右上 ⋯ → 通知設定）
  • 個人手機 LINE 通知是否關閉？
  • 若整個群組都沒收到 → 通知資訊室管理員依《更新手冊》F-10 排查

4.4 想加 / 退管理群組

  • 加人：請現有成員邀請加入
  • 退群：自行退出，不需通知管理員
  • 想換群組接收：通知資訊室管理員修改 LINE_ADMIN_GROUP_ID
