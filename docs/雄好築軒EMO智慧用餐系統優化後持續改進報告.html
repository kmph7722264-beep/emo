💡三、建議新增功能
📅多日預訂功能

允許使用者一次預訂未來 3–7 日的餐點，系統自動拆分為各日訂單。適合出差返勤計畫明確的同仁提前鎖位，減少當日截止前的訂單高峰。

前端後端中優先
✏️訂單自助修改

在結單截止時間前，使用者可在「我的訂單」頁自行修改餐點選項（早 / 中 / 晚），無需聯絡管理員取消後重訂。後端需確保修改操作的原子性與稽核記錄。

前端後端中優先
🔔餐點備妥通知

廚房人員在管理頁標記「某餐備妥」後，系統透過 LINE push 通知所有訂購該餐的使用者。取代現有廣播式群組訊息，僅通知有訂餐者，降低打擾。

後端LINE Bot中優先
🥗飲食偏好 / 過敏標記

使用者個人設定頁可填寫素食、過敏原（蛋 / 奶 / 花生等），訂餐時自動顯示警示提醒，廚房彙整通知亦標記特殊需求，降低錯發風險。

前端後端低優先
📊管理後台報表匯出

在管理頁新增「匯出 Excel」按鈕，可匯出指定日期範圍的訂單明細及月報統計，供財務、行政人員直接使用，免手動複製試算表。

前端後端低優先
📸菜單照片上傳

管理頁菜單編輯新增圖片上傳欄位（存至 Google Drive），使用者在菜單頁可看到當日各餐照片，提升點餐意願與正確率，減少「不知道是什麼」的投訴。

前端後端低優先
👥代訂功能（替他人訂餐）

允許長官或班長以自身帳號代替不使用 LINE 的同仁訂餐，填入代訂人姓名與電話，訂單標記「代訂」以利領餐核對，不影響黑名單統計。

前端後端低優先
🖨️廚房列印清單

結單後廚房可從管理頁點按「列印今日名單」，系統產生排版整齊的 PDF 列印預覽（依單位分組、標示特殊需求），取代手抄紙本作業。

前端低優先
🌐LINE 官方帳號選單整合

設定 LINE OA 的圖文選單，讓使用者直接從 LINE 對話頁點擊：訂餐 / 我的訂單 / 今日菜單，免記 LIFF 網址，大幅降低使用門檻。

LINE OA中優先
📈問卷分析儀表板

在管理頁新增「問卷統計」分頁，以折線圖顯示近 30 日平均評分趨勢、留言詞頻分析，幫助廚房快速掌握用餐滿意度變化。

前端後端低優先
💬公告推播功能

管理員可在管理頁輸入公告文字（例如「本週五停止供餐」），點按後透過 LINE Bot 推播給所有近 30 日有訂餐紀錄的 userId，取代目前手動群組發訊。

後端LINE Bot中優先
🔄週期性菜單範本

管理頁支援設定「週期菜單」（例如每週一固定菜色），系統可自動套用至未來日期，免每日手動輸入。菜單有異動時仍可個別覆蓋。

前端後端低優先
⚖️四、法規合規現況
✅ 已符合
  • 個資蒐集目的告知（個資法第 8 條）
  • 使用者書面同意（勾選同意框）
  • Referrer 防洩漏（no-referrer）
  • 通訊加密（HTTPS / LINE LIFF）
  • LINE ID Token 驗證（LINE Verify API）
  • 管理操作稽核記錄（AuditLog）
  • 問卷連結 HMAC 簽章（不可偽造）
⚠️ 部分符合（需補強）
  • 電話顯示已遮罩，但後端回傳未遮罩（待補）
  • 個資保存期限已說明，但未自動執行清除
  • 隱私告知已揭露，但未提供書面版本索取管道
  • 管理員帳號停用機制已建立，離職流程需補充 SOP
❌ 尚未符合
  • 個資自動匿名化機制未實作（超過保存期限後）
  • 未設置個資事故應變計畫（需制定 SOP）
  • 未提供使用者查閱 / 更正 / 刪除個資的管道
  • API 端點缺乏來源驗證（任何人可呼叫）

🔧七、技術債務清單
項目 問題描述 建議處理方式 緊急程度
LIFF ID 硬編碼 6 個 LIFF ID 直接寫在 HTML 的 <script> 中，換環境需人工逐一修改 改用環境設定檔或 GAS 動態回傳 LIFF ID 清單 低
API_URL 硬編碼 每支 LIFF 頁面都有相同的 API_URL 常數，GAS 重新部署後需 6 個頁面同步更新 抽取至共用 config.js，或透過 liff.init() 後向 GAS 查詢 endpoint 低

GAS 無自動化測試 後端修改後無法自動驗證，完全依賴人工測試，容易在版本迭代中引入回歸錯誤 使用 GAS Clasp + Jest 建立單元測試；或建立手動測試腳本 runAllTests() 中
Orders 表欄位依賴順序 後端大量使用 COL.XXX 數字索引，Schema 變更（加欄 / 移欄）極易造成資料錯位 加入 Schema 版本驗證函式，啟動時確認表頭順序是否符合預期 中
錯誤處理不一致 部分 handler 拋出例外（由頂層 catch 接住），部分回傳 { ok: false }，行為不統一 統一改為各 handler 內部 try/catch，回傳標準化 { ok, reason, error } 結構 低
📌八、結語與優先行動建議

本次資安強化大幅提升了系統的防禦縱深，從前端的隱私告知、電話遮罩、CDN 供應鏈消除，到後端的輸入淨化、重複訂單防護、管理員停用機制，以及錯誤訊息管控，已達到適合機關內部使用的基本安全水準。

然而，資料備份機制的缺失目前是最高風險點——一旦試算表發生意外，所有訂單與問卷資料將無從復原。建議在部署本次更新後，優先完成每日自動備份觸發器的設定。其次，API 速率限制與後端電話遮罩應於近期一併完成，使個資保護形成完整閉環。
