A. 日常更新 SOP（任何小修改）

每次改 Code.gs / order.html / admin.html / style.css 都套用以下流程。

A-1　改後端（Code.gs）

  1. 開 script.google.com 進到 EMO 專案
  2. 左側點 Code.gs → 全選（Ctrl+A）→ 貼上新版 → Ctrl+S 存檔
  3. （若新版有 migrateToVx 函式）函式下拉 → 選該函式 → ▶ 執行 → 看執行記錄確認結果
  4. （若新版要求新指令碼屬性）齒輪「專案設定 → 指令碼屬性」新增
  5. 右上 部署 → 管理部署作業
  6. 找到既有部署（前端 LIFF 用的 /exec），點右側 ✏️ 編輯
  7. 「版本」下拉 → 新版本 → 說明欄填變更摘要 → 部署
  8. /exec 網址不會變，前端不用動

⚠️ 千萬不要點「新增部署作業」。那會給你一條全新的 /exec 網址，前端 LIFF 的 API_URL 沒跟著改的話就會連不到 — 這是 GAS Web App 升級最大的地雷。永遠用「編輯既有部署 + 新版本」。

A-2　改前端（HTML / CSS）

  1. 開 GitHub repo（例如 emo-liff）→ 點該檔（admin.html / order.html / style.css）
  2. 右上 ✏️ 編輯 → 全選刪除 → 貼上新版 → 滑到下方 Commit changes
  3. 等 1～2 分鐘 GitHub Pages 重新發布
  4. 手機 LIFF 開啟 → 右上 ⋯ → 重新載入（強制清快取）

⚠️ 動 admin.html / order.html 時，不要動最上面兩行：

const LIFF_ID = '...您部署時填過的值...';
const API_URL = '...您部署時填過的值...';

整段貼上時請保留這兩行原值。

A-3　動了指令碼屬性

新版若需要新增或修改屬性（例如本次 v6 多一個 LINE_KITCHEN_GROUP_ID），在 A-1 第 2 步存檔後、第 5 步部署前到「專案設定 → 指令碼屬性」處理。屬性變更不需要重新部署，但建議一起做完。

B. 歷史升級紀錄：v5 → v6（新訂單通知改成 LINE 群組）

📌 此章為 v5 → v6 那一輪的完整步驟，保留作為歷史紀錄與排查參考。 若您現在要升級到目前最新版（v9），請改看 V7直升V9手冊.md。

本次不動 Sheet 結構（沒有 migrateToVx），主要在 LINE 設定面。 預估時間：20 ～ 30 分鐘（含建群、邀 Bot、測試）。

本次變更摘要

項目 v5 v6
新訂單通知對象 個別 DM 給 Admins ∪ KitchenStaff push 到一個指定的 LINE 群組
指令碼屬性 SHEET_ID / LINE_CHANNEL_ID / LINE_CHANNEL_ACCESS_TOKEN 新增 LINE_KITCHEN_GROUP_ID
KitchenStaff 工作表 用來收個人 userId 不再使用（舊資料可保留，無影響）
LINE Webhook 未使用 首次升級時短暫啟用（用來自動抓 groupId）
LINE OA「允許加入群組」 不需要 必須開啟（否則 Bot 一加入就被踢）
訂購人收到的訂單確認卡片 — 不變
Orders / Menu / Admins 工作表結構 — 不變
訂餐頁、管理頁前端 — 不變（這次只動後端 + LINE 設定）

升級流程總覽

階段一 貼新版 Code.gs（先不部署）
階段二 LINE OA Manager 開「允許 Bot 加入群組」
階段三 LINE Console 設 Webhook URL（先打開）
階段四 建立廚房群組、邀請 Bot、群內發訊息 → groupId 自動寫入屬性
階段五 跑 testKitchenGroupPush 驗證
階段六 重新部署 GAS Web App
階段七 實地下一張訂單驗證
階段八 收尾（關閉 Webhook，建議）

階段一　貼新版 Code.gs

  1. 開 script.google.com → 進 EMO 專案
  2. 左側點 Code.gs → 全選（Ctrl+A）→ 貼上 C:\emo\gas\Code.gs 整份內容 → Ctrl+S
  3. 此時不要部署，線上仍跑 v5，使用者不受影響

階段二　開啟「允許 Bot 加入群組」

LINE 預設禁止 Bot 加群，這顆開關沒打開，Bot 被邀進群會立刻自動退出。

  1. 開 manager.line.biz → 選對應的 OA（與你 Messaging API channel 同名那支）
  2. 左側 設定 → 回應設定
  3. 「加入群組或多人聊天」 切成 ON
  4. 順便確認同頁：
    • Webhook = ON（下一階段要用）
    • 自動回應訊息 = OFF（避免群組被罐頭訊息洗版）
  5. 儲存

階段三　設定 Webhook URL

  1. 開 developers.line.biz/console → 你的 Messaging API channel（不是 Login channel）
  2. 上方 Messaging API 分頁
  3. Webhook URL 填現有的 /exec 網址（與 LIFF 用的同一支）
  4. Use webhook = 開啟
  5. Verify 按一下：回 200 最佳；非 200 通常也能用，下一階段實測

階段四　建群、邀請 Bot、抓 groupId

  1. LINE 上建立群組（例如「EMO 廚房接單群」），把實際接單的廚房同仁加入

  2. 群組內邀請 Bot：群組設定 → 邀請 → 搜尋 Bot 名稱或 Basic ID（@xxxx）

  3. 確認 Bot 留在群裡沒被自動踢出

    • 若秒退 → 階段二沒做完整，回去再確認「允許加入群組」是否真的開啟

  4. 群內隨便發一則訊息（任何成員都可以、內容不拘）

  5. 回 Apps Script 編輯器，函式下拉選 debugKitchenGroupConfig → ▶ 執行

  6. 看下方執行記錄：

    LINE_KITCHEN_GROUP_ID    : Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LINE_CHANNEL_ACCESS_TOKEN: 已設定

  7. 看到 groupId（C 開頭 33 字元）就成功；若仍顯示 (未設定)，跳到 D 章「故障排除」對照

階段五　測試群組推播

  1. 函式下拉選 testKitchenGroupPush → ▶ 執行

  2. 執行記錄應顯示：

    testKitchenGroupPush → HTTP 200
groupId: Cxxxxxxx...
response: (空)

  3. 廚房群組應收到一則「📣 EMO 系統測試訊息 …」

  4. 若 HTTP 非 200，看 response 內容對照 D 章排查

階段六　重新部署 GAS Web App

  1. 右上 部署 → 管理部署作業
  2. 找到既有部署（前端 LIFF 用的 /exec），右側 ✏️ 編輯
  3. 「版本」下拉 → 新版本
  4. 說明欄填：v6 群組推播
  5. 部署
  6. 確認 Web App URL 結尾是 /exec，與舊版相同

⚠️ 不要點「新增部署作業」，理由見 A-1。

階段七　實地驗證

  1. 手機 LINE 開訂餐 LIFF（強制重新整理：右上 ⋯ → 重新載入）
  2. 下一筆測試訂單：單位=測試、訂購人=您、警用電話=0900-000-000、日期=今天
  3. 確認：
    • ✅ 訂購人本人 LINE 收到「✅ 訂單已收到」綠色 Flex（含訂單編號徽章與 QR）
    • ✅ 廚房群組收到「🍱 新訂單」橘色 Flex（不再是個別 DM）
    • ✅ Sheet Orders 多一筆，欄位齊全
  4. 若群組沒收到 → 看 Apps Script 左側「執行記錄」最新一筆是否有 New-order group push failed，依錯誤對照 D 章

階段八　收尾（建議）

  1. 回 LINE Developers Console → Messaging API channel
  2. Use webhook 切回 關閉（或留著也可，LINE_KITCHEN_GROUP_ID 已寫入後新事件會被略過）
  3. 群組裡的閒聊就不會持續打 GAS，節省一點配額

階段九　LINE 公告（可選）

在管理員 / 廚房群組貼：

📢 EMO 系統升級完成：

  • 新訂單通知改為發到本群組（不再 DM 個別人員）
  • 廚房成員不需再加 Bot 為好友
  • 訂餐頁、訂單編號、訂購人確認卡片皆未變更

C. 還原（萬一升級失敗要回 v5）

C-1　還原 GAS 程式

  1. 右上 部署 → 管理部署作業
  2. ✏️ 編輯既有部署 → 「版本」下拉選前一個版本（部署說明寫 v5 那次）→ 部署

還原後直接跑回 v5 multicast 個別 DM。前提是 KitchenStaff 工作表與舊 userIds 還在（升級時並沒有刪掉它們，只是停止讀取）。

C-2　還原指令碼屬性 / OA 設定

  • LINE_KITCHEN_GROUP_ID 屬性留著無害，v5 不會讀
  • LINE OA「允許加入群組」要關回去可關；對 v5 不影響
  • Webhook 也可關回去

D. 故障排除

Bot 一加進群組就自動退出

  • LINE OA 的「允許加入群組或多人聊天」沒開 → 回階段二

群內發了訊息，debugKitchenGroupConfig 仍顯示 (未設定)

  • Webhook URL 沒設或設錯（不是 /exec）→ 回階段三
  • Webhook 沒按「Use webhook → 開啟」
  • /exec 還在跑 v5 舊版（沒處理 webhook）→ 確認階段一真的存了檔；若已在階段六重新部署完，重發一則訊息再試
  • 訊息真的沒送出（群組權限被 LINE 限制等）→ 嘗試從別人帳號發

testKitchenGroupPush 回 HTTP 401

  • LINE_CHANNEL_ACCESS_TOKEN 失效或被換新 → 回 Messaging API channel 重新 Issue 一次，把新 token 填回指令碼屬性

testKitchenGroupPush 回 HTTP 400 或 bot is not a member

  • Bot 已被踢出群 → 重新邀請
  • groupId 與目前所在群不符 → 刪除 LINE_KITCHEN_GROUP_ID、重做階段三～四

訂單成立但群組沒收到通知（測試 push OK，只在實際下單失敗）

  • 看 Apps Script 執行記錄最新一筆，多半有 New-order group push failed: ... 訊息
  • 常見原因：token 在那時剛失效、群組剛被解散、Bot 剛被踢
  • 訂單仍會寫入 Sheet，只是通知沒送達 — 客人不受影響

想換群組

  1. 「專案設定 → 指令碼屬性」刪除 LINE_KITCHEN_GROUP_ID
  2. LINE Console 重開 Webhook（若已關）
  3. 把 Bot 邀請到新群、群內發一則訊息
  4. 跑 debugKitchenGroupConfig 確認新 groupId 已寫入
  5. Webhook 視需要關回

F-4　階段二：決定管理群組策略

選項 A（推薦給小單位）：管理群組 = 廚房群組

  • 不必新增任何屬性 / 群組
  • 廚房同仁也會看到每日日報與月報

  • 進入階段三

F-5　階段三：抓管理群組 groupId（選項 B 才需要）

  1. 建立管理 LINE 群組（例如「EMO 管理通知」），把主管 / 管理員加入
  2. 邀請 Bot 進群：群組設定 → 邀請 → 搜尋 Bot 名稱或 Basic ID（@xxxx）
  3. 確認 Bot 沒有自動退出（若秒退表示 OA「允許加入群組」沒開，回 B 章階段二）
  4. 回 LINE Developers Console → Messaging API channel → Messaging API 分頁
  5. Use webhook 暫時切回 開啟
  6. 管理群組內隨便發一則訊息
  7. 回 Apps Script「執行記錄」，找最新一筆類似： 
    Webhook group/room ids received but property already set; ignoring:
[{"type":"group","id":"Cxxxxxxxxxxxxxxxx..."}]
  8. 複製 C 開頭 33 字元的 groupId
  9. 至 Apps Script 齒輪「專案設定 → 指令碼屬性」
  10. 新增：屬性名稱 LINE_ADMIN_GROUP_ID，值為剛剛的 groupId → 儲存

💡 webhook 自動寫入 LINE_KITCHEN_GROUP_ID 的邏輯只在屬性未設時觸發；廚房群組已設過，所以新群組要手動填入。

F-7　階段五：測試推送

測試日報

  1. 函式下拉選 testDailyReportPush → ▶ 執行（參數欄留空）
  2. 執行記錄：OK: 已推送 YYYY-MM-DD 日報到管理群組
  3. 管理群組收到「📊 EMO 日報 (YYYY-MM-DD)」訊息，含：
    • 訂單總計、有效 / 已取消數
    • 三餐 訂 / 領 / 棄
    • 中餐 A / B / C 分項
    • 領餐率、棄單率
    • 訂購單位 TOP 5

測試月報

  1. 函式下拉選 testMonthlyReportPush → ▶ 執行（參數欄留空，預設上個月）
  2. 執行記錄：OK: 已推送 YYYY-MM 月報到管理群組
  3. 管理群組收到「📊 EMO 月報 (YYYY-MM)」訊息，含：
    • 涵蓋工作日數
    • 累計訂單數、有效 / 已取消
    • 三餐累計、中餐 A / B / C
    • 領餐率、棄單率
    • 單位 TOP 10
    • 棄單紀錄 TOP 5

💡 想測試特定月份：執行 testMonthlyReportPush 時參數填 2026-04

  4. 說明欄填：v11 統計日報 / 月報

  6. 確認 Web App URL 結尾是 /exec，與舊版相同

⚠️ 不要點「新增部署作業」，理由見 A-1。

F-9　階段七：收尾

  1. 若階段三打開了 Webhook，回 LINE Developers Console → Messaging API channel → Use webhook 切回關閉

  2. 把測試訊息從管理群組撤回（可選）

  3. 公告管理群組：

    📢 EMO 系統 v11 升級完成：

    • 每日 18:00 後 5 分鐘內，本群會自動收到當日統計日報
    • 每月 1 日 09:00，本群會自動收到前月月報摘要
    • 內容：訂單總計、三餐統計、領餐率、棄單率、單位排行
    • 訂餐頁、廚房群組彙整通知、現有領餐流程皆不變

F-10　v11 故障排除

日報 / 月報沒送出

  • 看 Apps Script「執行記錄」最新一筆，是否有 Daily report push failed / Monthly report push failed
  • 跑 debugKitchenGroupConfig：LINE_KITCHEN_GROUP_ID 是否設定？（fallback 群組）
  • 若設了 LINE_ADMIN_GROUP_ID：Bot 是否還在管理群組裡？被踢出就送不出
  • LINE_CHANNEL_ACCESS_TOKEN 是否仍有效？跑 testKitchenGroupPush 驗證

想強制重送

  • 跑 clearReportSentFlag()（清今日日報 + 上月月報鎖鍵）
  • 或直接跑 testDailyReportPush / testMonthlyReportPush（不檢查鎖鍵）

想換管理群組

  1. 刪指令碼屬性 LINE_ADMIN_GROUP_ID
  2. 重做階段三（重邀 Bot、抓新 groupId、寫入屬性）

想暫停 v11 推送

  • 「觸發條件」→ 找 checkAndSendDueReports → ⋮ → 刪除
  • 重新啟用：再跑一次 setupV11ReportTrigger

testDailyReportPush 回 HTTP 400 / bot is not a member

  • 與 D 章相同：Bot 已被踢出群 → 重新邀請
  • 或 LINE_ADMIN_GROUP_ID 設錯 → 重抓
