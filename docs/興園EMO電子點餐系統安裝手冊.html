EMO 電子點餐系統 — 手把手安裝手冊 (v11)

適用對象：第一次安裝、不熟悉程式的使用者。 完成時間：約 80 分鐘（不含等待 GitHub Pages 生效時間；v11 報表設定多約 10 分鐘）。

全程在電腦瀏覽器操作（建議 Chrome 或 Edge），最後用手機 LINE 測試。

v11 重點功能（首次安裝即內建）：

  • 每張訂單有專屬編號 YYYYMMDD-NNN，LINE 卡片帶編號與 QR 條碼，領餐時憑編號或掃碼核對
  • 早 / 中 / 晚餐各自獨立標記領餐；管理頁三餐分別統計、可只看未領餐
  • 菜單可依日期個別維護，歷史菜單自動保留；某日未設定的餐別自動沿用最近一日
  • 中餐 A / B / C 各設每日 40 份上限，超量自動拒收
  • 棄單偵測 + 黑名單：逾時未領自動標棄單；30 天內棄單超過 3 次停權 30 天
  • 新訂單通知 push 到一個指定的 LINE 群組（廚房內部群）— 廚房成員不必逐一加 Bot 好友
  • 每餐結單彙整推送（v10）：早 07:00 / 中 10:30 / 晚 16:00 結單後，每餐自動推送 1 則彙整訊息至廚房群組
  • AuditLog 操作稽核（v9）：管理員所有動作（標領 / 掃 QR / 取消 / 改菜單）全程紀錄
  • 取消訂單軟刪除（v8）：管理員可手動取消，保留原始資料以利稽核
  • 取餐時段 QR 自動判餐別（v7）：早 07–08 / 中 11:30–12:30 / 晚 16:50–18:00
  • ★ v11 統計日報 / 月報自動推送：
    • 每日 18:00（晚餐領餐時段結束）後 5 分鐘內，自動推送當日統計至管理 LINE 群組 （訂單總計、三餐 訂/領/棄、中餐 A/B/C、領餐率、棄單率、訂購單位 TOP 5）
    • 每月 1 日 09:00 自動結算前月並推送月報摘要 （工作日數、累計訂單、領餐率、棄單率、單位 TOP 10、棄單紀錄 TOP 5）
    • 管理頁亦可即時查詢任意日期 / 月份的報表並匯出 Excel

0. 在開始之前，請先準備好

  • 一個 Google 帳號（Gmail）
  • 一個 LINE 帳號（手機需可正常使用）
  • 一個 GitHub 帳號（沒有的話 5 分鐘可註冊）
  • 一台電腦，建議使用 Chrome 或 Edge 瀏覽器
  • 本專案資料夾 C:\emo\（已建立完成）
  • 一份記事本，等等需要記下幾段 ID / 網址：
    • Sheet ID
    • LINE_CHANNEL_ID（Login channel）
    • LINE_CHANNEL_ACCESS_TOKEN（Messaging API channel）
    • 訂餐 LIFF ID
    • 管理 LIFF ID
    • GAS Web App /exec 網址
    • 廚房群組 ID（後段由 Webhook 自動取得，不需手動記）
  • 一個廚房內部 LINE 群組（可先建好，至少包含實際接單同仁）
  • 一個管理 LINE 群組（v11 新增；用於接收每日 18:00 日報與每月 1 日 09:00 月報；可與廚房群組共用，但建議分群）

第一階段：建立 Google 試算表

預估 5 分鐘。這份試算表會自動收到所有訂單。

Step 1-1　建立試算表

  1. 用 Chrome 開啟 https://sheets.google.com
  2. 用 Gmail 帳號登入
  3. 點擊「＋ 空白」建立新試算表
  4. 點左上角「未命名的試算表」改名為 EMO 點餐

Step 1-2　複製 Sheet ID（重要！）

  • 瀏覽器網址列看起來像： 
    https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKl_xxx_xxxxx_1234567890/edit
                                     └──────────── 這段就是 Sheet ID ───────┘
  • 反白複製 /d/ 與 /edit 中間那一長串，貼到記事本。

第二階段：建立 Apps Script（後端程式）

預估 10 分鐘。Apps Script 是 Google 內建的免費伺服器服務。

Step 2-1　開啟 Apps Script 編輯器

  1. 在剛建立的 EMO 點餐 試算表內
  2. 上方選單：擴充功能 → Apps Script
  3. 會自動跳出新分頁，顯示空白程式編輯器

Step 2-2　貼上後端程式碼

  1. 編輯器預設有一段 function myFunction() {}，全選刪除
  2. 用記事本打開 C:\emo\gas\Code.gs，全選 → 複製
  3. 回到 Apps Script 編輯器，貼上
  4. 按下 Ctrl + S 儲存
  5. 左側檔案區，把專案名稱（最上方）改為 EMO 點餐後端

Step 2-3　顯示並貼上 appsscript.json

  1. 左側點齒輪「專案設定」
  2. 勾選「在編輯器中顯示「appsscript.json」資訊清單檔案」
  3. 回左側「編輯器」，會多一個 appsscript.json 檔案
  4. 點開它，把專案 C:\emo\gas\appsscript.json 的內容整段取代進去
  5. 儲存

Step 2-4　設定指令碼屬性（Step 1 取得的 Sheet ID 派上用場）

  1. 左側齒輪「專案設定」→ 拉到最下方「指令碼屬性」
  2. 點「新增指令碼屬性」
  3. 屬性名稱：SHEET_ID；值：剛剛複製的 Sheet ID
  4. 點「儲存指令碼屬性」
  5. （LINE_CHANNEL_ID 與 LINE_CHANNEL_ACCESS_TOKEN 等第三、四階段取得後再回來補）

Step 2-5　執行初始化（會建立 3 個工作表）

  1. 回到左側「編輯器」
  2. 程式碼頂部下拉選單選 setupSheets → 點 執行 ▶
  3. 第一次會跳「需要授權」：
    • 點「審查權限」→ 選擇您的 Google 帳號
    • 若出現「Google 尚未驗證這個應用程式」警告：
      • 點左下「進階」
      • 點「前往 EMO 點餐後端（不安全）」
      • 點「允許」
    • 解釋：這是您自己寫的程式不在 Google 公開市集，警告屬正常。
  4. 執行成功後，回到試算表分頁，下方會多出 3 個工作表分頁：
    • Orders（20 欄：時間戳記／單位／訂購人／警用電話／訂購日期／早餐／中餐便當／晚餐便當／備註／LINE userId／訂單編號／早餐已領／早餐領餐時間／中餐已領／中餐領餐時間／晚餐已領／晚餐領餐時間／早餐棄單／中餐棄單／晚餐棄單）
    • Menu（4 欄：日期／餐別／餐點名稱／更新時間）
    • Admins（3 欄：LINE userId／名稱／備註）

💡 訂單編號、各餐領餐狀態、棄單欄位都由系統自動寫入，您不需要手動處理。 💡 v6 後新訂單通知改用 LINE 群組推播，不再需要 KitchenStaff 工作表（舊版升級時即使留著也無影響）。

第三階段：申請 LINE Login Channel

預估 10 分鐘。這是讓使用者「用 LINE 帳號進入點餐頁」用的。

Step 3-1　登入 LINE Developers

  1. 開啟 https://developers.line.biz/console/
  2. 用 LINE 帳號掃 QR Code 或輸入信箱密碼登入
  3. 第一次登入可能會請您填開發者名稱與信箱

Step 3-2　建立 Provider（如已有可跳過）

  1. 點「Create」→ Create a new provider
  2. Provider name：例如 EMO 工作室
  3. 點 Create

Step 3-3　建立 LINE Login Channel

  1. 進入剛建立的 Provider
  2. 點 Create a new channel → 選 LINE Login
  3. 填寫：
    • Region：Taiwan
    • Channel name：EMO 點餐
    • Channel description：電子點餐系統
    • App types：勾選 Web app
    • 同意條款 → Create
  4. 進入 channel，找到 Channel ID（一串數字，例如 2007123456）
  5. 複製此 ID，貼到記事本，命名 LINE_CHANNEL_ID

Step 3-4　把 Channel ID 補回 Apps Script

  1. 回 Apps Script 分頁 → 齒輪「專案設定」→「指令碼屬性」
  2. 新增：屬性 LINE_CHANNEL_ID，值為上一步的 Channel ID
  3. 儲存

第四階段：申請 LINE Messaging API Channel（推播用）

預估 10 分鐘。這是訂單成立後自動發 LINE 訊息給訂購人與廚房用的。

⚠️ 必須與 Step 3 的 Login Channel 在同一個 Provider 底下，否則 userId 不通。

Step 4-1　回 Provider 建立第二個 channel

  1. 點上方麵包屑回到 Provider 頁
  2. Create a new channel → 選 Messaging API
  3. 填寫：
    • Channel name：EMO 點餐機器人
    • Channel description：訂單通知
    • Category / Subcategory：選最接近「餐飲」的選項
    • 同意條款 → Create

Step 4-2　取得 Channel Access Token

  1. 進入剛建立的 Messaging API channel
  2. 上方分頁切到「Messaging API」
  3. 拉到頁面最下方 Channel access token
  4. 點「Issue」按鈕（如果寫 Reissue 也是一樣）
  5. 產生一段很長的字串（約 170 字元），全選複製
  6. 貼到記事本，命名 LINE_CHANNEL_ACCESS_TOKEN

Step 4-3　補進 Apps Script 指令碼屬性

  1. 回 Apps Script → 齒輪「專案設定」→ 指令碼屬性
  2. 新增：屬性 LINE_CHANNEL_ACCESS_TOKEN，值為剛剛的 token
  3. 儲存
  4. 此時三個屬性應齊全：
    • ✅ SHEET_ID
    • ✅ LINE_CHANNEL_ID
    • ✅ LINE_CHANNEL_ACCESS_TOKEN

Step 4-4　OA Manager 三項設定（自動回覆 / 允許加群 / Webhook）

  1. 還在 Messaging API 分頁，找到 Auto-reply messages 區塊 → 點 Edit
  2. 會跳到 LINE Official Account Manager → 進入對應 OA
  3. 左側 設定 → 回應設定，做以下三件事：
    • 「自動回應訊息」 → 停用（避免群組被罐頭訊息洗版）
    • 「加入群組或多人聊天」 → 開啟 ON ⚠️ 本版必設，否則 Bot 被邀進廚房群會立刻自動退出
    • 「Webhook」 → 開啟 ON（第八階段會用到，先打開備著）
  4. 「歡迎訊息」可保留預設，或改為：「歡迎光臨，您將透過此帳號收到訂單通知。」
  5. 儲存

Step 4-5　記下 Bot 的加好友連結（僅訂購人需要）

  • Messaging API 分頁上方有 Basic ID（@xxxxxxxx）或 QR code
  • 截圖或記下，訂購人必須先加此 Bot 為好友才會收到自己的訂單確認推播
  • v6 後廚房成員不必個別加 Bot，新訂單通知會發到群組

第五階段：把網頁上傳到 GitHub Pages（免費託管）

預估 15 分鐘（含等 Pages 生效）。

Step 5-1　建立 GitHub 帳號（已有可跳過）

  1. https://github.com/signup
  2. 完成註冊、信箱驗證

Step 5-2　建立 Repository

  1. 登入後右上角「＋」→ New repository
  2. Repository name：emo-liff
  3. Public（免費版 Pages 需要公開）
  4. 勾選 Add a README file
  5. Create repository

Step 5-3　上傳 liff 資料夾的檔案

  1. 進入剛建立的 repo
  2. Add file → Upload files
  3. 開啟檔案總管 C:\emo\liff\
  4. 將下列檔案拖曳到 GitHub 上傳區：
    • order.html
    • admin.html
    • style.css
    • preview.html（可選，僅樣式預覽用）
  5. 滑到下方 Commit changes（保留預設）
  6. 等待上傳完成

Step 5-4　啟用 GitHub Pages

  1. Repository 上方 Settings → 左側 Pages
  2. Source：選 Deploy from a branch
  3. Branch：選 main，資料夾 /(root) → Save
  4. 等 1～2 分鐘，頁面頂端會出現： 
    Your site is live at https://你的GitHub帳號.github.io/emo-liff/
  5. 兩個重要網址（記到記事本）：
    • 訂餐頁：https://你的帳號.github.io/emo-liff/order.html
    • 管理頁：https://你的帳號.github.io/emo-liff/admin.html
  6. 用瀏覽器先打開測試是否能載入。會看到「LIFF 初始化失敗」是正常的，因為還沒填 LIFF ID。

第六階段：建立兩個 LIFF App

預估 5 分鐘。

Step 6-1　回 LINE Login Channel 加入 LIFF

  1. 回 LINE Developers → 進入 Login Channel（注意：不是 Messaging API channel）
  2. 上方分頁切到 LIFF
  3. 點 Add

Step 6-2　建立「訂餐」LIFF

  • LIFF app name：EMO 訂餐
  • Size：Full
  • Endpoint URL：貼上 Step 5-4 的訂餐頁網址
  • Scopes：勾 profile、openid
  • Bot link feature：On (Aggressive) — 讓使用者進入時自動提示加 Bot 好友
  • Scan QR：可不勾
  • Add

加入後產生一組 LIFF ID（格式：1234567890-AbcdEfgh），複製到記事本，命名「訂餐 LIFF ID」。

Step 6-3　建立「管理」LIFF

重複 Step 6-2，但：

  • name：EMO 管理
  • Endpoint URL：貼上管理頁網址
  • Scan QR：⚠️ 必須勾選 ✅（v5.1 起，管理員領餐時掃 QR 條碼會用到）

複製產生的 LIFF ID，命名「管理 LIFF ID」。

⚠️ 注意：兩個 LIFF ID 不一樣，等等填入網頁時不要弄混。

第七階段：部署 GAS Web App，並把 ID 填入網頁

預估 5 分鐘。

Step 7-1　部署 Apps Script

  1. 回 Apps Script 編輯器
  2. 右上 部署 → 新增部署作業
  3. 左側齒輪 → 選 網頁應用程式
  4. 填寫：
    • 說明：v1
    • 執行身分：我
    • 存取權：所有人
  5. 點 部署
  6. 若跳授權，按 Step 2-5 流程允許
  7. 完成後會顯示一個網址： 
    https://script.google.com/macros/s/AKfycb.../exec
  8. 複製到記事本，命名「GAS Web App 網址」

Step 7-2　修改 order.html

  1. 用記事本或 VS Code 開啟 C:\emo\liff\order.html
  2. 找到開頭的兩行： 
    const LIFF_ID = '__PASTE_LIFF_ID__';
const API_URL = '__PASTE_GAS_WEBAPP_URL__';
  3. 將 __PASTE_LIFF_ID__ 替換為 訂餐 LIFF ID
  4. 將 __PASTE_GAS_WEBAPP_URL__ 替換為 GAS Web App 網址
  5. 儲存

Step 7-3　修改 admin.html

  • 同 7-2，但 LIFF ID 替換為 管理 LIFF ID（API_URL 與 order.html 相同）

Step 7-4　重新上傳到 GitHub

  1. 回 GitHub repo
  2. 點開 order.html → 右上鉛筆圖示 ✏️ 編輯
  3. 整段刪除，貼上修改後的內容
  4. 滑到下方 Commit changes
  5. 同樣處理 admin.html
  6. 等 1～2 分鐘 Pages 重新生效

Step 7-5　把 /exec 網址回填到 Messaging API Webhook

  1. 回 LINE Developers Console → 你的 Messaging API channel
  2. 上方 Messaging API 分頁
  3. Webhook URL 填 Step 7-1 的 GAS /exec 網址
  4. Use webhook 確認是 開啟（Step 4-4 已經先開好）
  5. 按 Verify：回 200 最佳；非 200 通常也能用，下一階段實測

第八階段：設定管理員與廚房群組

預估 5 分鐘。

Step 8-1　取得您自己的 LINE userId

  1. 手機開 LINE
  2. 用 LINE 的「行動條碼掃描」掃 LIFF 的 QR Code
    • QR Code 位置：LINE Developers → Login Channel → LIFF 分頁 → 點開「訂餐 LIFF」右邊有 QR
  3. 第一次會要求 LINE 登入授權 → 允許
  4. 進入訂餐頁後，隨便填一筆測試訂單送出（單位:測試, 訂購人:測試, 警用電話:0900-000-000, 日期:今天）
  5. 回電腦上的試算表 → Orders 工作表
  6. 看最右欄 LINE userId，那一串 U... 開頭的 33 字元就是您的 userId
  7. 複製

Step 8-2　登錄管理員

  1. 切到 Admins 工作表
  2. 第 2 列填入： | A 欄: LINE userId | B 欄: 名稱 | C 欄: 備註 | |---|---|---| | Uxxxxxxxxxxxxxxxx... | 您的名字 | 主管理員 |

Step 8-3　設定廚房 LINE 群組（取得 groupId）

v6 後新訂單通知統一發到一個指定群組，廚房成員不必個別加 Bot 好友。

  1. 建立或選定廚房內部群組（Step 0 已準備），把實際接單同仁加入
  2. 邀請 Bot 進群組：群組設定 → 邀請 → 搜尋 Bot 名稱或 Basic ID（@xxxx）
  3. 確認 Bot 留在群組沒有自動退出
    • 若秒退 → Step 4-4 的「允許加入群組或多人聊天」沒開，回去確認
  4. 群內隨便發一則訊息（任何成員都可以、內容不拘）
  5. 回 Apps Script 編輯器
    • 函式下拉選 debugKitchenGroupConfig → 點 ▶ 執行
    • 看下方執行記錄應顯示： 
      LINE_KITCHEN_GROUP_ID    : Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LINE_CHANNEL_ACCESS_TOKEN: 已設定
  6. groupId（C 開頭 33 字元）出現就成功，屬性已自動寫入，不需要手動貼
  7. 測試群組推播：函式下拉選 testKitchenGroupPush → ▶ 執行
    • 廚房群組應立刻收到一則「📣 EMO 系統測試訊息 …」
    • 執行記錄顯示 testKitchenGroupPush → HTTP 200

🛠 完成後，可回 LINE Developers Console 把 Use webhook 切回關閉，避免群組閒聊持續打到 GAS（屬性已寫入後新事件會被略過，留著也無害）。 🛠 若想換群組：刪除指令碼屬性 LINE_KITCHEN_GROUP_ID、重開 Webhook、把 Bot 邀請到新群、新群內發一則訊息即可重新捕捉。

第九階段：完整測試

預估 10 分鐘。

Step 9-1　管理員測試

  1. 手機 LINE 掃「管理」LIFF 的 QR Code 進入
  2. 應看到「管理員後台」+ 訂單統計區 + 領餐快速查詢區 + 餐點維護表單
  3. 在「每日餐點維護」：
    • 「適用日期」預設今天
    • 把五個餐別填入（例：早餐=飯糰、中餐 A=滷雞腿便當…）→ 儲存當日菜單
    • 出現綠色「已更新 YYYY-MM-DD 的菜單」訊息 ✅
  4. 預先設定明天的菜單（驗證多日菜單）：
    • 把「適用日期」改成明天 → 按「載入該日菜單」
    • 表單會自動帶入今天的菜單作為基底（fallback 機制）
    • 改其中一項（例：中餐 A 改成「明日測試 A」）→ 儲存當日菜單
  5. 「當日訂單統計」：選今天日期 → 查詢
    • 應看到 9 格統計卡片（總筆數 / 早餐 / 晚餐 / 中餐 A / 中餐 B / 中餐 C / 早餐已領 X/Y / 中餐已領 X/Y / 晚餐已領 X/Y）
    • Step 8 的測試訂單應出現在明細，含訂單編號徽章與三列三餐 meal-row（各自獨立的未領 / 已領狀態）

Step 9-2　訂餐端測試

  1. 手機 LINE 掃「訂餐」LIFF 的 QR Code
  2. 確認下拉選單裡顯示剛剛設定的餐點名稱（且切換日期到明天時，中餐 A 顯示「明日測試 A」）
  3. 切回今天，填寫並送出訂單
  4. 觀察：
    • ✅ 網頁顯示「訂單已送出，感謝您！　您的訂單編號：YYYYMMDD-NNN（請於領餐時出示）」
    • ✅ 您（訂購人）的 LINE 收到「✅ 訂單已收到」綠色卡片，頂端含訂單編號徽章與 QR
    • ✅ 廚房群組收到「🍱 新訂單」橘色卡片，含訂單編號（不是個別 DM 給廚房人員）
    • ✅ 試算表 Orders 多出一筆，K 欄寫入訂單編號、L / N / P 三個「已領」欄為 FALSE

Step 9-3　領餐功能測試

  1. 回管理 LIFF（強制重新整理） → 「當日訂單統計」重新查詢今天
  2. 找到剛剛 Step 9-2 送的測試訂單（橘色「未領」徽章）
  3. 點「標記已領」按鈕
    • ✅ 卡片底色由琥珀變綠
    • ✅ 徽章變「已領 ✓」、按鈕變「取消已領」
    • ✅ 上方對應餐別的「已領 X/Y」統計即時 +1（早 / 中 / 晚三組獨立計）
  4. 試「領餐快速查詢」：
    • 在輸入框打 Step 9-2 收到的訂單編號（例 20260519-001） → Enter
    • 應顯示該單卡片（綠色已領狀態）
  5. 切到 Orders 工作表
    • L 欄該列應為 TRUE
    • M 欄該列應有時間戳

Step 9-4　如有任一步失敗

  • 翻到最後一章「常見問題排查」對照

第十一階段：v11 統計日報 / 月報自動推送設定

預估 10 分鐘。此階段需在第八階段（廚房群組）設定完後再做。

Step 11-1　準備管理 LINE 群組

  1. 建立或選定一個管理 LINE 群組（建議與廚房群組分群，避免廚房同仁看到內部統計）
  2. 把實際需要看日報 / 月報的人員加入（管理員、主管、單位幹部等）
  3. 邀請 Bot 進管理群組：群組設定 → 邀請 → 搜尋 Bot 名稱或 Basic ID（@xxxx）
  4. 確認 Bot 留在群組沒有自動退出（與第八階段一樣，OA Manager「允許加入群組」必須開啟）

Step 11-2　取得管理群組 ID

廚房群組 ID 已自動寫入 LINE_KITCHEN_GROUP_ID（第八階段）。
此步要再抓一個新的 groupId 寫入 LINE_ADMIN_GROUP_ID。

作法 A（推薦，最省事）：管理群組與廚房群組合併使用同一個

  • 若您打算用同一個 LINE 群組同時收「廚房接單通知」與「管理日報 / 月報」，不必做任何事
  • GAS 在找管理群組時，會先看 LINE_ADMIN_GROUP_ID；沒設定就退而使用 LINE_KITCHEN_GROUP_ID
  • 直接跳到 Step 11-3

作法 B（分群推薦）：管理群組與廚房群組分開

  1. 回 LINE Developers Console → Messaging API channel
  2. Webhook URL 仍為 /exec 網址
  3. Use webhook 暫時切回 開啟
  4. 在管理群組內隨便發一則訊息
  5. 回 Apps Script 編輯器，函式下拉選 debugKitchenGroupConfig → ▶ 執行
    • 若顯示「廚房群組 ID 已設定」，但新群組無法自動寫入，因為 webhook 設計只在屬性未設時寫一次。請改用作法 C 手動填入。

作法 C（最可靠）：手動填入 LINE_ADMIN_GROUP_ID

  1. 用[作法 B 1～4 步]觸發 webhook，到 Apps Script「執行記錄」找最近一筆 Webhook group/room ids received but property already set; ignoring: [{...,"id":"Cxxxx..."}]
  2. 複製 C 開頭的 33 字元 groupId
  3. 至 Apps Script 齒輪「專案設定 → 指令碼屬性」
  4. 新增：屬性名稱 LINE_ADMIN_GROUP_ID，值為剛剛的 groupId
  5. 儲存

Step 11-3　建立日報 / 月報自動推送 trigger

  1. 回 Apps Script 編輯器
  2. 函式下拉選 setupV11ReportTrigger → ▶ 執行
  3. 第一次會跳授權，按之前流程允許
  4. 執行記錄應顯示：已建立每 5 分鐘執行 checkAndSendDueReports 的 trigger（v11 日報 / 月報自動推送）
  5. 左側「觸發條件」可看到新增的 checkAndSendDueReports time-based 觸發

Step 11-4　測試日報推送

  1. 函式下拉選 testDailyReportPush → ▶ 執行（參數欄留空，預設今天）
  2. 執行記錄顯示：OK: 已推送 YYYY-MM-DD 日報到管理群組
  3. 管理群組應立刻收到一則「📊 EMO 日報 (YYYY-MM-DD)」純文字訊息
  4. 訊息內容應包含：訂單總計、三餐 訂 / 領 / 棄、中餐 A / B / C、領餐率、棄單率、訂購單位 TOP 5

Step 11-5　測試月報推送

  1. 函式下拉選 testMonthlyReportPush → ▶ 執行（參數欄留空，預設上個月）
  2. 執行記錄顯示：OK: 已推送 YYYY-MM 月報到管理群組
  3. 管理群組應收到一則「📊 EMO 月報 (YYYY-MM)」純文字訊息

💡 若想指定月份手動測試：執行 testMonthlyReportPush 時參數欄填 2026-04

Step 11-6　日常自動觸發確認

  • 日報：每日 18:00 之後 5 分鐘內，trigger 會自動推送當日日報
    • 鎖鍵 DAILY_REPORT_SENT_{date} 確保每日只送 1 次
    • 失敗不寫鍵，下次 5 分鐘 trigger 自動重試
  • 月報：每月 1 日 09:00 之後 5 分鐘內，trigger 會自動推送前月月報
    • 鎖鍵 MONTHLY_REPORT_SENT_{yyyy-MM} 確保每月只送 1 次
  • 若要強制重送：執行 clearReportSentFlag()（清今日日報 + 上月月報鎖鍵）後等下次 trigger，或直接跑 testDailyReportPush / testMonthlyReportPush

Step 11-7　收尾

  • 若作法 B / C 期間打開了 Webhook，請回 LINE Console 把 Use webhook 切回關閉（避免群組閒聊持續打到 GAS）
  • 把測試訊息從管理群組撤回（可選）

常見問題排查

Q1：送出訂單後沒收到 LINE 確認推播

  • ☐ 您加 Bot 為好友了嗎？（未加好友就收不到）
  • ☐ LINE_CHANNEL_ACCESS_TOKEN 屬性是否填對？（最容易少貼或多空格）
  • ☐ Apps Script → 左側「執行記錄」是否有 LINE push failed 字樣？點開看詳情

Q2：管理頁顯示「無管理員權限」

  • ☐ Admins 工作表的 userId 是否與您本人 userId 完全一致？（注意大小寫）
  • ☐ userId 是否在 A 欄（第一欄）？
  • ☐ 第 1 列是表頭，您的資料應該從第 2 列開始

Q3：訂餐頁下拉選單只有「不訂購」選項

  • ☐ 管理員是否已透過管理頁設定當日餐點？
  • ☐ 直接打開 Menu 工作表，B 欄是否有餐點名稱？

Q4：統計查詢顯示「無管理員權限」

  • 同 Q2

Q5：廚房群組沒收到新訂單通知

  • ☐ Apps Script「執行記錄」最新一筆是否有 New-order group push failed？訊息會指出原因
  • ☐ 在編輯器跑 debugKitchenGroupConfig 確認 LINE_KITCHEN_GROUP_ID 已設定
  • ☐ 跑 testKitchenGroupPush 是否回 HTTP 200？
    • HTTP 401 → LINE_CHANNEL_ACCESS_TOKEN 失效，重新 Issue 並更新屬性
    • HTTP 400 / bot is not a member → Bot 已被踢出群組，重新邀請
  • ☐ Bot 還在群組裡嗎？（被踢出就收不到）
  • ☐ 若想換群組 → 刪屬性、重開 Webhook、重邀 Bot、群內發訊息

Q6：修改 admin.html 後，瀏覽器看不到更新

  • 強制重新整理：Ctrl + F5
  • GitHub Pages 生效有 1～2 分鐘延遲
  • 確認您是修改後重新上傳到 GitHub，不是只改本機檔案

Q7：GAS 程式改了之後沒生效

  • Apps Script 改程式後必須 重新部署版本：
    • 右上「部署 → 管理部署作業」
    • 點現有部署右上角鉛筆 ✏️
    • 「版本」選 新版本 → 填說明 → 部署
  • ✅ API_URL 不會變，不需要再改 HTML
  • ⚠️ 千萬不要點「新增部署作業」 — 那會給你一條全新的 /exec 網址，前端 LIFF 就連不到了。日常更新永遠用「編輯既有部署 + 新版本」。詳見 更新手冊.md A 章。

Q8：LIFF 開啟時跳 LIFF init failed: invalid liffId

  • 您填的 LIFF ID 不對。
  • 注意：訂餐 LIFF ID ≠ 管理 LIFF ID，兩個檔案要填各自的。

Q9：試算表的 訂購日期欄看起來像 2026/05/15 而不是 2026-05-15，統計查不到

  • Google 試算表可能自動格式化日期。
  • 解法：選取 D 欄 → 上方功能表「格式 → 數值 → 純文字」，再請使用者重新送一筆訂單測試。
  • 或：保留試算表顯示格式不動，後端會自動正規化日期比對（已內建）。

Q10：要新增 / 移除管理員

  • 直接編輯試算表 Admins 工作表即可，不需要重新部署 GAS，下次呼叫即時生效

Q10-1：要新增 / 移除廚房接單同仁

  • v6 後接單同仁是「LINE 群組成員」概念，直接在群組裡踢出 / 邀請即可
  • 群組本身不變、LINE_KITCHEN_GROUP_ID 不變，新訂單通知就會自動發給目前群裡的所有成員

Q11：訂購人說「沒收到訂單編號」

  • ☐ 是否最近才升級 / 上線？訂購人可能是 GitHub Pages 快取的舊頁面 → 請對方 LIFF 右上 ⋯ → 重新載入
  • ☐ 訂單編號永遠會生成並寫入 Sheet 的 K 欄，畫面沒顯示只是前端問題；可請對方先到 LINE 看 Flex 卡片頂端的編號徽章

Q12：訂餐頁切換日期，菜單卻沒變

  • 這是預期的 fallback 行為：該日若未設定，會自動沿用最近一個更早日期的菜單
  • 若想讓某日顯示空白或不同菜單，請到管理頁「每日餐點維護」→ 「適用日期」選該日 → 明確儲存該日菜單

Q13：管理頁明細中有些訂單沒有訂單編號徽章

  • 通常出現在從舊版升級的情境；新安裝不會發生
  • 若您是新安裝就看到這狀況，到 Orders 工作表確認該列 K 欄是否為空。若為空，到 Apps Script 執行 migrateToV3 一次補回

Q14-1：v11 日報 / 月報沒送出

  • ☐ Apps Script 「執行記錄」是否有 Daily report push failed / Monthly report push failed？
  • ☐ 跑 debugKitchenGroupConfig：LINE_KITCHEN_GROUP_ID 是否設定？（fallback 來源）
  • ☐ 若設了 LINE_ADMIN_GROUP_ID，Bot 是否還在管理群組裡？被踢出就送不出
  • ☐ LINE_CHANNEL_ACCESS_TOKEN 是否仍有效？跑 testKitchenGroupPush 驗證 token 還活著
  • ☐ 跑 testDailyReportPush（忽略鎖鍵）若 OK 表示 token / groupId 都對，問題是 trigger 沒觸發 → 「觸發條件」確認 checkAndSendDueReports 仍存在
  • ☐ 若鎖鍵被誤設導致同日不會再送，跑 clearReportSentFlag() 清除

Q14-2：v11 日報想換 / 取消推送

  • 換群組：刪 LINE_ADMIN_GROUP_ID → 重設新 groupId（重做 Step 11-2）
  • 暫停推送：「觸發條件」→ 找 checkAndSendDueReports → 右側 ⋮ → 刪除
    • 重新啟用：再跑一次 setupV11ReportTrigger

Q15：菜單想要「強制把某日設為不供應某餐別」

  • 在管理頁「每日餐點維護」→ 適用日期選該日 → 把該餐別欄位清空 → 儲存當日菜單
  • 系統會在 Menu 工作表寫入該日該餐別為空字串（不再 fallback）
  • 訂餐頁該餐別會自動消失於下拉選單

維護與備份建議

  • 每月備份：試算表 → 檔案 → 下載 → Excel (.xlsx)，存到本機
  • 換 Bot：重新核發 Access Token，更新 GAS 指令碼屬性 LINE_CHANNEL_ACCESS_TOKEN 即可，不需重新部署
  • 要查歷史訂單：直接打開試算表 Orders 工作表查詢、篩選、樞紐分析
    • K 欄訂單編號可作為唯一識別；L 欄「已領餐」可篩選未領訂單回查
  • 要匯出某日訂單給廚房：在 Orders 工作表用上方「資料 → 建立篩選器」依日期篩選，列印或複製貼到 Word
  • 歷史菜單追溯：Menu 工作表保留所有日期的菜單紀錄；要看某日歷史菜單，用 A 欄篩日期即可
