第一章

系統概述

1.1　系統緣起與目的

雄好竹軒智慧用餐系統（以下簡稱「本系統」）係為改善雄好竹軒傳統紙本或口頭訂餐作業所衍生之人力耗費、統計錯誤及餐點浪費等問題，所建置之數位化訂餐管理平台。

本系統以 LINE 應用程式為載體，透過 LIFF（LINE Front-end Framework）技術，使全體用餐人員得於手機上完成訂餐、查詢菜單及填寫回饋問卷等作業，無需額外安裝任何應用程式。

1.2　系統效益
⏱️

降低行政作業時間

訂餐、統計、廚房通知全程自動化，每日省去人工匯整工作。

📉

減少餐點備料浪費

精確統計各餐實際訂購量，廚房依數備料，有效降低剩餘。

📊

提供決策數據支援

日報、月報自動推送，棄單率統計，協助管理層掌握用餐趨勢。

🛡️

強化個資保護

符合個人資料保護法規範，電話遮罩、操作稽核，保障人員隱私。

第三章

使用者角色與權限

3.1　角色定義
角色身份說明驗證方式可使用功能
一般用餐人員 使用 LINE 訂餐的全體同仁 LINE 帳號登入（LIFF 自動） 查詢菜單、線上訂餐、查詢個人訂單、填寫問卷
管理員 食堂管理人員、指定行政人員 LINE userId 登錄於 Admins 工作表 以上全部，加上：標記領餐、取消訂單、更新菜單、查詢所有訂單、操作稽核、報表查詢、QR 掃描領餐
自動化系統 GAS 時間觸發器 系統排程觸發 棄單偵測、結單彙整推播、日報 / 月報推播
3.2　管理員帳號管理

管理員資格由系統管理人員直接維護 Google Sheets「Admins」工作表。

欄位說明範例
A 欄：LINE userIdLINE 帳號唯一識別碼（U 開頭，44 碼字串）Uabcdef1234567890...
B 欄：名稱管理員顯示名稱，用於稽核記錄王小明
C 欄：停用日期填入 YYYY-MM-DD 格式後，到期日起自動停用管理員權限；空白表示持續有效2026-12-31
D 欄：備註自由填寫，不影響系統邏輯第一區值班管理員
⚠️ 管理員人員異動時，請立即於 C 欄填入停用日期（或刪除該列），以防止離職人員繼續擁有管理權限。
3.3　黑名單停權機制

為抑制惡意訂餐後棄單的行為，系統設有自動停權機制：

  • 滑動視窗：30 天內累計棄單次數
  • 停權門檻：棄單超過 3 次（第 4 次棄單時生效）
  • 停權期間：30 天（期滿自動解除）
  • 停權對象：僅限線上訂餐，現場點餐不受影響
  • 申訴管道：如有疑問請聯絡管理員手動調整
第四章

主要功能說明

4.1　每日菜單查詢

開放所有人員（含未登入狀態）查詢任意日期的菜單資訊，頁面載入時自動顯示當日菜單。

顯示資訊
  • 早餐：餐點名稱、結單時間（07:00）、訂購狀態（可訂購 / 已結單）
  • 中餐 A / B / C：各品項名稱、剩餘份數（上限 40 份 / 品項）、訂購狀態
  • 晚餐：餐點名稱、結單時間（16:00）、訂購狀態
  • 未來日期顯示「未來日期」標籤；過去日期顯示「已結單」
結單時間
餐別結單時間說明
早餐每日 07:00逾時當日早餐不可訂購
中餐每日 10:30逾時當日中餐不可訂購
晚餐每日 16:00逾時當日晚餐不可訂購
4.2　線上訂餐

已登入 LINE 帳號的人員可透過訂餐頁面選擇餐點並送出訂單，系統於訂單確認後即時推播 LINE 訊息至使用者。

訂餐流程
1
開啟訂餐頁面

透過 LINE OA 選單或連結進入，系統自動以 LINE 帳號登入，並從歷史訂單自動帶入單位、姓名、電話資料。

2
選擇訂購日期

預設為今日，可切換至未來日期。系統自動顯示各餐可訂購狀態及中餐剩餘份數。

3
勾選餐點

早、中、晚餐分別以勾選方式選取；中餐需指定 A / B / C 品項（各品項每日上限 40 份）；未勾選任一餐別視為不訂購該餐。

4
填寫備註並同意個資告知

備註欄為選填（上限 200 字）；首次使用須閱讀並勾選個人資料保護告知事項。

5
送出訂單

系統驗證資料無誤後寫入訂單，並透過 LINE Bot 推播「訂單確認卡片」（含 QR Code 及問卷連結）。

訂單確認卡片內容
  • 訂單編號（格式：YYYYMMDD-NNN）
  • 單位、訂購人、警用電話、訂購日期
  • 各餐選項
  • 領餐用 QR Code（領餐時向管理員出示）
  • 用餐回饋問卷快速連結
  • 棄單規則提醒
ℹ️ 同一使用者在同一日期僅可送出一筆訂單。如需修改，請聯絡管理員取消原訂單後重新訂購。
4.3　現場點餐（walkin 模式）

提供無法提前線上訂餐之人員（如臨時加班、訪客等）於食堂現場直接完成點餐作業。

現場點餐時段
餐別現場受理時間
早餐07:00 – 08:10
中餐10:30 – 12:40
晚餐16:00 – 17:40
與線上訂餐的差異
  • 中餐不分 A/B/C 品項，亦不受 40 份上限限制
  • 訂單不發送 LINE 確認通知（現場操作）
  • 不受黑名單停權限制（管理員代客下單）
  • 備註欄自動標記「【現場點餐】」以利識別
  • 可掃描既有訂單 QR 自動帶入歷史訂購人資料
4.4　我的訂單

使用者可查詢個人最近 50 筆訂單的完整狀態，無需聯絡管理員即可掌握訂餐及領餐情形。

顯示資訊
  • 訂單編號、訂購日期、各餐選項
  • 各餐領餐狀態：已領（含領餐時間）/ 未領 / 已棄單
  • 訂單取消狀態及原因
  • 問卷填寫狀態
Tab 切換
  • 全部訂單：顯示所有訂單，含已取消
  • 待填問卷：篩選出當日或過去未填問卷且未取消的訂單，快速進入問卷填寫
4.5　用餐回饋問卷

系統於訂單確認時即自動附上問卷連結，使用者可於當日 24:00 前填寫，每筆訂單限填一次。

問卷內容
  • 整體滿意度（必填，1–5 分）
  • 餐點品質（必填，1–5 分）
  • 服務態度（必填，1–5 分）
  • 文字建議（選填，上限 500 字）
問卷安全機制
  • 連結含 HMAC-SHA256 數位簽章，無法偽造或複製給他人使用
  • 連結僅限本人、當日有效，逾時自動失效
  • 每筆訂單僅可填寫一次，重複填寫時系統予以拒絕
4.6　管理員功能
訂單查詢
  • 依日期查詢當日全部訂單，含各餐人數統計
  • 依訂單編號或姓名快速搜尋特定訂單
  • 顯示各訂單的領餐狀態、取消狀態、備註
領餐標記
  • 手動標記：點擊訂單卡片上的餐別按鈕，逐筆標記已領
  • QR 掃描標記：於領餐時段內掃描使用者手機上的 QR Code，系統依當下時間自動判斷對應餐別並標記
  • 已標記的時間自動記錄（格式：HH:mm），不可重複標記
訂單取消
  • 管理員可取消任一訂單（軟刪除，資料保留）
  • 取消後自動釋出中餐 A/B/C 名額供他人訂購
  • 取消原因、操作者名稱及時間均記錄於訂單及稽核記錄
  • 已取消訂單不列入棄單統計
菜單管理
  • 新增或更新任意日期的早 / 中餐 A、B、C / 晚餐菜色
  • 系統採「最近適用日期」邏輯：某日若未設定菜單，自動沿用最近一筆歷史菜單
  • 可查詢菜單更新歷史記錄
操作稽核記錄

所有管理員操作（標記領餐、取消訂單、更新菜單等）均自動寫入 AuditLog 工作表，可在管理頁依日期或動作類型查詢，供事後稽核或爭議處理。

4.7　QR Code 領餐驗證

每筆訂單確認後，使用者的 LINE 訊息中均附有專屬 QR Code，供領餐時向管理員出示掃描。

掃描時段
餐別QR 掃描受理時間時段外處理
早餐07:00 – 08:00時段外掃描一律拒絕，改由管理員手動點按標記
中餐11:30 – 12:30
晚餐16:50 – 18:00
掃描結果判斷
  • 訂單存在 + 當前時段有訂該餐 + 尚未標記 → 自動標記已領，顯示訂購人資訊確認
  • 訂單已取消 → 顯示錯誤，不可標記
  • 該餐已領 → 提示重複，回傳原領餐時間
  • 該訂單無訂此餐 → 顯示錯誤
4.8　統計報表
每日結單彙整（自動推送）

每餐結單後，系統自動推送彙整訊息至廚房 LINE 群組，內容包含：

  • 訂購名單（單位、姓名、品項、備註、自備餐具標記）
  • 各品項數量統計（中餐分 A/B/C 計數）
  • 已取消訂單獨立列出（標明不需準備）
每日統計日報（自動推送）

每日 18:00 後自動推送至管理群組，內容包含：

  • 訂單總計（有效 / 已取消）
  • 三餐各別訂購數 / 領餐數 / 棄單數
  • 中餐 A / B / C 各別數量
  • 整體領餐率 / 棄單率
  • 訂購單位 TOP 5
  • 當日問卷回覆統計（份數、平均評分、留言摘要）
月報（自動推送）

每月 1 日 09:00 自動推送前月月報，額外包含：

  • 涵蓋工作日數
  • 訂購單位 TOP 10
  • 棄單紀錄 TOP 5（含單位、姓名）
  • 問卷平均評分（整體 / 餐點 / 服務）
💡 管理員亦可在管理頁手動查詢任意日期或月份的統計數據，無需等待自動推送。
第五章

自動化機制

本系統設有多支定時觸發器（Time-based Trigger），由 Google Apps Script 排程自動執行，無需人工介入。

觸發器名稱執行頻率功能說明設定方式
棄單偵測
markAbandonedOrders		 每 10 分鐘 掃描訂單，將超過棄單 cutoff（早 08:00 / 中 12:30 / 晚 18:00）且尚未領餐、未取消的訂單標記為棄單 執行 setupAbandonmentTrigger()
結單彙整推播
checkAndSendDueSummaries		 每 5 分鐘 每餐結單後首次執行時，推送該餐訂購彙整至廚房 LINE 群組；鎖鍵確保每餐每日只推送一次 執行 setupOrderSummaryTrigger()
日報 / 月報推播
checkAndSendDueReports		 每 5 分鐘 每日 18:00 後推送日報；每月 1 日 09:00 後推送前月月報；鎖鍵確保每次只推送一次 執行 setupV11ReportTrigger()
⚠️ 以上三支觸發器需於 GAS 部署後各執行一次對應的 setup 函式方可啟動。請確認 LINE_KITCHEN_GROUP_ID 及 LINE_CHANNEL_ACCESS_TOKEN 等必要設定均已填入指令碼屬性。
第六章

資訊安全設計

6.1　身份驗證機制
  • 所有 LIFF 頁面均透過 LINE 平台進行 OAuth 2.0 身份驗證，未登入者自動導向 LINE 登入頁面
  • 後端每次 API 請求均呼叫 LINE Verify API（oauth2/v2.1/verify）驗證 ID Token 真偽，不信任前端傳入的使用者資訊
  • Token 有效期限約 1 小時，前端設有到期前 5 分鐘警示提示使用者重新整理
6.2　資料傳輸安全
  • 前端至後端的所有通訊均透過 HTTPS 加密傳輸
  • 所有頁面設有 Referrer-Policy: no-referrer，防止 LIFF URL（含使用者 token 參數）洩漏至第三方服務
  • 問卷連結採 HMAC-SHA256 數位簽章，確保連結無法偽造或轉讓

  • LINE LIFF SDK 仍使用官方 CDN（static.line-scdn.net），由 LINE 官方維護
6.5　管理員權限控管
  • 管理員身份以 LINE userId 為唯一依據，僅在 Admins 工作表中登錄者方具管理權限
  • Admins 工作表 C 欄可設定停用日期，到期後自動撤銷管理員資格
  • 所有管理員操作均記錄於 AuditLog（操作者、時間、動作、目標、結果），可事後稽核

個人資料保護

依個人資料保護法第 8 條規定，本系統於使用者首次訂餐前提供以下告知事項，並要求勾選同意後方可送出訂單：

告知項目內容
蒐集目的提供雄好竹軒訂餐服務

利用期間服務存續期間內
保存期限訂單資料保存 1 年
利用對象本系統管理人員（食堂作業用途）

7.2　電話號碼保護
  • 管理頁面顯示電話號碼時，採用遮罩格式（例：091****78），防止無關人員瀏覽螢幕時看到完整號碼
  • 完整號碼僅儲存於 Google Sheets，存取權限限於試算表擁有者及明確授權人員

所有個人資料均儲存於 Google Sheets（由本單位 Google 帳號持有），儲存地點遵循 Google Workspace 資料處理條款。系統不將個人資料傳送至 Google 及 LINE 以外的任何第三方服務。

7.4　當事人權利

依個人資料保護法，使用者享有查閱、更正、刪除個人資料之權利。如需行使上述權利，請聯繫本單位系統管理員，由管理員於 Google Sheets 中協助處理。
