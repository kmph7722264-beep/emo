B. 各版本逐項變更詳述

v1（2025-09）規劃

  • 需求訪談（訂購人 / 廚房 / 管理員）
  • 架構選型：LINE LIFF + Google Apps Script + Google Sheets（零伺服器、零授權費）
  • Orders 工作表初版（9 欄）：時間戳記 / 單位/姓名 / 電話 / 訂購日期 / 早餐 / 中餐便當 / 晚餐便當 / 備註 / LINE userId
  • Menu 工作表初版（3 欄 × 5 列）：餐別 / 餐點名稱 / 更新時間
  • LIFF order.html / admin.html 雛形

v2（2025-10）基礎建置

  • Orders 欄位調整：「單位/姓名」拆為「單位」+「訂購人」（兩欄皆必填）；「電話」改為「警用電話」標籤
  • 中餐每日上限：A / B / C 各 40 份；剩餘量即時顯示，售完自動禁選
  • Admins 工作表新增（3 欄：LINE userId / 名稱 / 備註），白名單控管管理頁進入
  • Orders 結構：9 欄 → 10 欄
  • 遷移函式：migrateOrdersToV2（純加欄，可重複執行）

v3（2025-11）訂單管理

  • 訂單編號 YYYYMMDD-NNN：每日從 001 流水，每筆訂單唯一可追蹤
  • 多日菜單：Menu 重構為 4 欄（日期 / 餐別 / 餐點名稱 / 更新時間），保留歷史
    • 某日未設定的餐別自動沿用最近一日（fallback）
  • 領餐確認：Orders 加「已領餐」「領餐時間」兩欄；管理頁可一鍵標記
  • QR 條碼：LINE 訂單確認卡片頂端附訂單編號 QR
  • 未領餐統計：管理頁可篩選「只看未領」
  • 領餐快速查詢：輸入訂單編號 → 顯示該單 → 一鍵標領
  • 新增 POST action：markPickup、findOrder
  • Orders 結構：10 欄 → 13 欄
  • 遷移函式：migrateToV3（含 Orders + Menu，含訂單編號回填）

v4（2025-12）領餐優化

  • 領餐欄位拆成三餐各自：
    • 早餐已領 / 早餐領餐時間 / 中餐已領 / 中餐領餐時間 / 晚餐已領 / 晚餐領餐時間
  • markPickup 必填參數 meal：breakfast | lunch | dinner
  • stats / findOrder 回傳 per-meal 領餐狀態
  • 管理頁三餐分別統計（9 格統計卡片：總筆數 / 早 / 晚 / A / B / C / 早領 / 中領 / 晚領）
  • Orders 結構：13 欄 → 17 欄
  • 遷移函式：migrateToV4（純加欄）

v5（2026-01）紀律機制

  • 棄單偵測 + 黑名單：
    • Orders 加 3 欄（早餐棄單 / 中餐棄單 / 晚餐棄單，boolean）
    • 新增 markAbandonedOrders：自動將超過時段未領、未取消的訂單標棄單
    • 30 天內棄單 > 3 次 → 自動停權 30 天（handleOrder_ 黑名單檢查）
  • 進單結單時間管控：早餐 07:00 / 午餐 10:30 / 晚餐 16:00 後不可訂購當日該餐
  • 訂購人 LINE 卡片補上「需修改/取消請聯絡管理員」與棄單規則說明
  • 部署後需執行 setupAbandonmentTrigger（每 10 分鐘掃描）
  • Orders 結構：17 欄 → 20 欄
  • 遷移函式：migrateToV5（純行為變更，無資料遷移）

v6（2026-02）群組通知

  • 新訂單通知改用 LINE 廚房群組 push，不再 multicast 個別人員
    • 廚房成員不必個別加 Bot 為好友
  • 新增指令碼屬性 LINE_KITCHEN_GROUP_ID，存放廚房群組 ID
  • groupId 自動捕捉機制：將 webhook URL 設為 GAS /exec，Bot 進群後群內發訊息 → doPost 寫入屬性
  • 廢除 KitchenStaff 工作表流程（舊資料保留無影響）
  • 移除 multicastNewOrder_ / testMulticast / debugNotifyList
  • 新增 pushNewOrderToGroup_ / testKitchenGroupPush / debugKitchenGroupConfig
  • LINE OA Manager 必須開啟「允許 Bot 加入群組或多人聊天」
  • Sheet 結構不變

v7（2026-03）時段管控

  • 取餐時段 PICKUP_WINDOW：早 07:00–08:00 / 午 11:30–12:30 / 晚 16:50–18:00
  • QR 掃描自動判餐別：新增 POST action scanPickup
    • 時段外 → 拒絕（out_of_window），改由手動按鈕標領
    • 該訂單沒訂該餐 → 拒絕（not_ordered）
    • 該餐已 picked → 拒絕（already_picked），回傳原 pickedAt
    • 同一餐被取消已領後再掃 QR → 允許重標
  • 棄單 cutoff 對齊取餐時段結束：
    • 早 07:00 → 08:00、晚 17:30 → 18:00（午餐 12:30 不變）
    • 語意：取餐時段結束仍未領 → 棄單
  • 由 v6 升級無需資料遷移，重新部署即生效
  • Sheet 結構不變

v8（2026-04）取消訂單

  • 訂單軟刪除：Orders 加 4 欄（已取消 / 取消時間 / 取消操作者 / 取消原因）
  • 新增 POST action cancelOrder：管理員手動取消，保留原始資料以利稽核
    • 操作者寫入「管理員名稱 (userId)」格式
    • 已取消過的單會被拒絕（already_cancelled）防止覆蓋
  • 連帶排除 cancelled = TRUE 的訂單：
    • 中餐 A/B/C 名額釋出（getLunchCountsForDate_）
    • 棄單偵測略過（markAbandonedOrders）
    • 黑名單棄單統計不算（getBlockStatus_）
    • 領餐標記拒絕（handleMarkPickup_ / handleScanPickup_）
    • 統計獨立計（counts.cancelled）
  • Orders 結構：20 欄 → 24 欄
  • 遷移函式：migrateToV8（純加欄）

v9（2026-04）操作稽核

  • 新增 AuditLog 工作表（7 欄）：時間戳記 / 操作者 userId / 操作者名稱 / 動作 / 目標 / 細節 / 結果
  • 四個 admin handler 全面寫入 audit log（含成敗）：
    • markPickup / scanPickup / cancelOrder / updateMenu
  • 新增 POST action listAuditLog：管理頁可查詢操作歷程
    • body: { date?, action?, limit? (default 200, max 1000) }
  • 由 v8 升級：重新部署後執行一次 setupSheets（會自動建 AuditLog 工作表）
  • 不影響既有資料或既有功能

v10（2026-05）額度節省

  • 廚房群組通知改為「每餐結單後彙整一次」（節省 LINE 額度）
    • 移除每筆下單時的 push 到群組（原 pushNewOrderToGroup_ 與 buildKitchenFlex_ 刪除）
    • 新增 checkAndSendDueSummaries：依 ORDER_CUTOFF 過後推送該餐當日彙整
      • 訊息內容：訂購人名單（單位/姓名/品項/備註）、餐量分項統計、總訂單數、已取消註記
      • 中餐分 A/B/C 計數；早/晚餐只計總數
      • 已取消訂單獨立列表標明「不需準備」、不計入製作量
    • 一次只發 1 則純文字訊息（最省 quota），長度上限 4900 字
    • Script Property 鎖鍵 SUMMARY_SENT_{meal}_{date} 確保每餐每日只送 1 次
  • 部署後需執行 setupOrderSummaryTrigger（每 5 分鐘掃描）
  • 手動測試：testMealSummaryPush('2026-05-21', 'lunch')（忽略 idempotency 強制送）
  • 效果：月推播由「每筆下單 push 群組」改為「每餐 1 則彙整」，降低 80%↑
    • 原設計 3,300 則/月 → 新設計 66 則/月
  • 個人 LINE 訂單確認卡片（含 QR）行為不變，仍逐單推送
