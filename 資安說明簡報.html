🛡 03 ｜ 現有安全防護機制 高雄市政府警察局 資訊室
防護面向 實施措施說明 狀態 對應法規
身份驗證 LINE ID Token（JWT）每次 API 請求均在後端驗證，Token 過期自動失效；未登入 LINE 帳號無法使用任何功能 ✓ 已實施 個資法第27條
管理員存取控管 Admins 白名單工作表由管理員維護，後台所有敏感功能（標領、取消、菜單）均需通過白名單驗證 ✓ 已實施 個資法第27條
操作稽核日誌 完整記錄所有管理員操作：標領、掃 QR、取消訂單、修改菜單，含操作人員、時間戳記、執行結果 ✓ 已實施 資安法第6條
傳輸加密 全程 HTTPS（TLS 1.2+）加密傳輸，包含 LINE SDK 通訊、Google API 呼叫及靜態頁面服務 ✓ 已實施 個資法第27條
跨站攻擊防護 XSS 防護（所有輸出使用 escapeHtml 函數處理）；CSRF 防護（ID Token 每次驗證，偽造請求無效） ✓ 已實施 資安法第6條
個資告知同意 訂餐前強制顯示個資告知條款，用戶需主動勾選同意後方可送出訂單（未勾選系統阻擋） ✓ 已實施 個資法第8條
資訊外洩防護 Referrer 資訊遮蔽（no-referrer）；快取控制（no-cache/no-store）；防止 LINE WebView 殘留舊版本 ✓ 已實施 個資法第27條
資料加密儲存 Google Sheets 欄位層級加密儲存（姓名、電話欄位），強化雲端資料保護 ◎ 規劃中 個資法第27條

⚖ 04 ｜ 資安風險評估 高雄市政府警察局 資訊室
本系統資安風險評估應聚焦於「資料實際敏感度」，而非平台技術名稱。以下為關鍵對比說明。
❌ 本系統「不涉及」的高風險資料
🚫 偵查案件資料（犯罪嫌疑人、偵查計畫）
🚫 勤務部署資訊（班表、巡邏路線、裝備）
🚫 個人住址、身份證字號
🚫 機密通訊頻道或密碼
🚫 武器彈藥管理資料
🚫 任何列管涉密業務文件
✅ 本系統「實際儲存」的資料
✔ 警員姓名（與 LINE 群組、電話簿相同層級）
✔ 警用內線分機（非涉密通訊頻道）
✔ 所屬單位（如 偵查隊、行政組）
✔ 訂餐記錄（今天吃什麼、是否自備餐具）
✔ LINE 帳號 ID（匿名識別碼，無法直接識別真人）
✔ 用餐滿意度（選填，可去識別化）
📌 風險結論：縱使 Google 雲端資料外洩，外部人士僅能得知「某 LINE 帳號在某警察局訂了什麼餐」，無法獲取任何業務敏感資訊。現行使用 LINE 群組訂餐的資料敏感度與本系統相當，本系統反而增加了存取控制與稽核能力。
